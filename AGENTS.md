# Instructions for AI agents

This checkout is the `workshop-baseline` branch of PyPSA-Eur, set up for the
PyPSA x AI workshop. The person you work for is one of four people in a group
that builds one study together.

Before you act on a request:

1. Read `workshop/README.md`: the study, the four roles and how the group works
   together.
2. Find out which role the person has. Ask if you do not know. Then read that
   role's file in `workshop/roles/`.
3. Before you run or change the model, read `workshop/BASELINE.md`: how to run
   it, what it assumes, and the memory limit of the workspace.

Every figure you make, in any role, uses the workshop plot style, so the
group's figures fit together: before you write plotting code, read
`.claude/skills/plot-style/SKILL.md` (code in `workshop/plotstyle/`).

The role file sets guardrails for a sensible contribution; stay within them.
Other people and their agents change the same workflow.

The group's binding design decisions are in `workshop/decisions.md`
(study design, economic parameters, scenarios). Follow them in every role.

The study's results are in `workshop/results/RESULTS.md`, generated by
`workshop/analysis/evaluate.py` (skill `results-pipeline`); the scenario runs
are steered by the skill `scenario-runs`, which builds on role 3's skill
`run-model`. Do not edit `RESULTS.md` by hand; findings go into
`workshop/results/notes.md`.

The final presentation is built by the skill `presentation` from
`workshop/presentation/` (outline `deck.yaml`, register of data, assumptions
and decisions `register.yaml`; guide in its `README.md`). Do not edit the
generated `.pptx` by hand.

## Confidential data (NDA)

Everything in `workshop/inputs/` is under NDA, in particular every term of the
financing term sheet: above all the offtake price and the guarantee terms of
the deal named there. Rule E7 in `workshop/decisions.md` applies:

- Read these files only at runtime, to validate public assumptions, and report
  only coarse bands (as `workshop/cba/validate_against_nda.py` does). Never use
  them as model input.
- Never write a confidential value, an exact ratio or difference that reveals
  one, the deal code or the guarantee terms into code, config, comments,
  commits, file names, logs, figures, slides or documentation, and never pass
  them to outside services.
- Never commit or push `workshop/inputs/`. Before sharing any output, check it
  holds no confidential value.
